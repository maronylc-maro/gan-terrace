# がんテラス セットアップ手順

Google Cloud やサービスアカウントは使わない。スプレッドシートに紐づく Apps Script 1本で、
サイトへのデータ配信と「気になる」の集計をまとめて行う。

## 1. リポジトリの準備
1. GitHubで新しいリポジトリを作成する
2. このフォルダの中身をすべてリポジトリにアップロード（push）する

## 2. GitHub Pagesを有効化
1. リポジトリの `Settings` → `Pages`
2. `Branch` を `main` / `/(root)` に設定して保存
3. 発行されたURLがサイトのアドレスになる

## 3. スプレッドシートの準備
同梱の `がんテラス_データ入力シート.xlsx` をGoogleドライブにアップロードし、
右クリック → `アプリで開く` → `Googleスプレッドシート` で変換する。
シート名（`events` / `news` / `facilities` / `purposes` / `purpose_items`）は変更しないこと。

### events シート（イベント）
| A:日時 | B:タイトル | C:場所 | D:概要 | E:詳細リンク | F:関連施設・団体名 |
|---|---|---|---|---|---|
| 2026-09-03 | 〇〇教室 | さくら総合病院 | 説明文 | https://... | さくら総合病院 |

- 日時は `2026-09-03` の形式で入力する（`2026/9/3` や `2026年9月3日` でも自動で変換される）
- F列（関連施設・団体名）は、`purpose_items` シートの施設・団体名と**完全に同じ文字列**を入れる。空欄でもよい

### news シート（お知らせ）
| A:日時 | B:タイトル | C:リンク |
|---|---|---|

### facilities シート（施設・団体リンク集）
| A:名称 | B:サイトURL | C:GoogleマップURL |
|---|---|---|

### purposes シート（目的別情報のカテゴリ）
| A:カテゴリID | B:カテゴリ名 | C:イラスト | D:説明文 |
|---|---|---|---|
| talk | 集う | talk.webp | 同じ経験をした人や相談員と話せる場を探せます。 |

- カテゴリIDは半角英数字。`purpose.html?cat=talk` のURLと、purpose_items との紐付けに使う
- イラストは**ファイル名だけ**を入力する。画像は `images` フォルダに置いておく必要がある

### purpose_items シート（カテゴリごとの施設・団体）
| A:カテゴリID | B:施設・団体名 | C:リンクURL |
|---|---|---|
| talk | 患者会 ひまわりの会 | https://... |

- A列には purposes シートのカテゴリIDと同じ文字列を入れる
- 1つのカテゴリに複数の施設・団体を入れる場合は、同じカテゴリIDで行を増やす
- B列の名称は、eventsシートのF列（関連施設・団体名）と揃えると関連イベントが強調表示される

1行目は見出し行、2行目からデータ。A列が空の行は読み込まれない。
スプレッドシートのURLから **スプレッドシートID** を控える。
`https://docs.google.com/spreadsheets/d/【ここがID】/edit`

## 4. Apps Script の設定
1. スプレッドシートで `拡張機能` → `Apps Script` を開く
2. `scripts/gas/Code.gs` の中身をすべて貼り付ける
3. 上部の `SPREADSHEET_ID` を手順3で控えたIDに書き換えて保存
4. 右上の `デプロイ` → `新しいデプロイ` → 種類を `ウェブアプリ` にして
   - 次のユーザーとして実行：`自分`
   - アクセスできるユーザー：`全員`
   でデプロイする（初回は権限の承認を求められる。「詳細」→「安全でないページに移動」で進む）
5. 発行された `https://script.google.com/macros/s/.../exec` を控える

このURLは手順5と手順7の両方で使う。

> **なぜ「全員」にするのか**
> GitHub Pages のサイトからも読めるようにするため。公開されるのはスプレッドシートの中身ではなく、
> このスクリプトが返すイベント・お知らせ・施設リンク集・目的別情報のデータだけ（いずれもサイトに載せる情報）。
> スプレッドシート本体は非公開のまま。

## 5. GitHub Secretsの設定
リポジトリの `Settings` → `Secrets and variables` → `Actions` で以下を登録する

| Secret名 | 内容 |
|---|---|
| `SHEETS_API_URL` | 手順4で控えたウェブアプリURL（`.../exec` まで） |

## 6. データを反映する
1. リポジトリの `Actions` タブを開く
2. 「スプレッドシートをサイトに反映」を選択
3. `Run workflow` ボタンを押す
4. 1分ほどで `data/` 以下のJSON（events / news / facilities / purposes）が更新され、サイトに反映される

スプレッドシートを編集しただけでは反映されない。編集のあとにこの手順を実行する。

## 7. 気になるボタンを有効にする
イベント詳細に表示される「👍 気になる」の件数は、手順4と同じApps Scriptに記録される。

1. `js/config.js` を開く
2. `window.LIKE_API_URL = '';` の `''` の中に、手順4のウェブアプリURLを貼り付ける
3. 保存してpushすると、イベント詳細に「気になる」ボタンと数字が表示される

URLが空のあいだはボタン自体が表示されないので、後から設定してもよい。
スプレッドシートに `likes` シートが自動で作られ、`日付|タイトル` のキーごとに件数が入る。
どのイベントに反応があったかはこのシートで確認できる。

### 仕様上の注意
- 同じ端末では1イベント1回まで（ブラウザに記録して二度押しを防ぐ）。端末やブラウザを変えれば再度押せるため、厳密な人数ではなく目安の数値
- スプレッドシートのイベント名や日付を後から変えるとキーが変わり、それまでの件数は引き継がれない
- Apps Script のコードを直したときは、`デプロイ` → `デプロイを管理` → 鉛筆アイコン → バージョンを「新バージョン」にして再デプロイしないと反映されない

## お問い合わせフォーム
各ページのフッターにある `https://forms.gle/your-google-form-id` を、実際のGoogleフォームURLに差し替える。
`index.html` `purpose.html` `calendar.html` `facilities.html` の4ファイルにある。

## 目的別情報の編集
`purposes` と `purpose_items` の2シートに入力し、他のデータと同じくActionsで反映する。
生成される `data/purposes.json` は自動で書き換わるので、手で編集する必要はない。

カテゴリを増やす場合は、`purposes` シートに行を追加し、`purpose_items` に同じカテゴリIDで
施設・団体を並べるだけでよい（HTMLの編集は不要）。新しいイラストを使う場合だけ、
画像ファイルを `images` フォルダに追加する作業が必要。

> **安全策**：`purposes` シートが空のまま反映を実行した場合、`data/purposes.json` は更新されない。
> 入力前にActionsを回してトップページの目的別情報が消える事故を防ぐため。

## ページ構成
| ファイル | 内容 |
|---|---|
| `index.html` | トップ（目的別情報のカード＋新着一覧）。メニューの「目的別情報」「新着一覧」はこのページ内へ移動する |
| `purpose.html` | 目的別情報の詳細。カードをクリックすると `purpose.html?cat=talk` の形で開き、上部のボタンでカテゴリを切り替える |
| `calendar.html` | イベントカレンダー（月／週／リスト表示、日付をタップでその日の一覧、Googleカレンダー追加） |
| `facilities.html` | 施設・団体リンク集 |

## ファイル構成
| 場所 | 内容 |
|---|---|
| `data/*.json` | サイトが読み込むデータ。すべて Actions が自動更新するので手で編集しない |
| `js/config.js` | 「気になる」ボタンのURL設定 |
| `scripts/gas/Code.gs` | スプレッドシート側に貼るApps Scriptのコード |
| `scripts/sync_sheets.py` | Actions が実行する同期スクリプト（追加パッケージ不要） |
| `.github/workflows/sync-data.yml` | Actions のワークフロー定義 |
| `images/` | 目的別情報のイラスト |
